Where new players land

Today each sign-up goes to the emptiest region, so the first players end up in different regions. In a local test, four sign-ups landed in four regions. The proposal fills one patch at a time. Lone active players get neighbours first, then a fresh patch opens beside the last one.

The shared record for the NPC and Alliances builds

One table says which colonies each player knows. Everything else (map, raid and send checks, NPC discovery, first contact) reads it through one server helper, so the next builds plug in without new rules.

known_coloniesWhat it holds
player_id, colony_idWho knows which colony (one row each, never deleted)
discovered_atWhen it stopped being a scent
viaHow: scouted, raided_you, scouted_you, earlier (seeded at launch). Later builds add their own, such as contact or ally

No row means a scent. Your own colonies are always known. The NPC build makes new NPCs ordinary colony rows (like wild nests today), so they show up as wild scents with no extra work.
